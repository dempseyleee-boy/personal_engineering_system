# TASK_CONTEXT_TEMPLATE.md

## 1. 模板作用

本模板用于生成单个任务的轻量任务上下文文件：

```text
task_context/TASK_CONTEXT.md
```

或按任务单独生成：

```text
task_context/tasks/TASK_CONTEXT_任务编号.md
```

该文件用于记录一个具体任务的目标、输入、输出、约束、相关文件、验证方式和完成标准。

它主要回答：

```text
这个任务具体要做什么？
输入是什么？
输出是什么？
有哪些约束？
要参考或修改哪些文件？
怎么判断任务完成？
怎么验证结果？
```

注意：

```text
本文件是通用模板，不绑定任何具体项目。
使用时，Agent 应根据当前任务实际情况，把【占位内容】替换为真实任务信息。
不要在模板中写入具体项目名称、具体技术路线或具体领域内容。
```

---

# 2. TASK_CONTEXT 与 CONTEXT_PACKAGE 的区别

```text
TASK_CONTEXT.md：
轻量级，聚焦单个任务本身。

CONTEXT_PACKAGE.md：
更完整，包含项目背景、用户偏好、历史决策、当前状态、相关命令、约束和完成标准。
```

简单理解：

```text
TASK_CONTEXT.md = 单个任务说明书
CONTEXT_PACKAGE.md = 本次任务完整上下文包
```

当任务较简单时，可以只生成 `TASK_CONTEXT.md`。

当任务较复杂、跨多个文件、涉及项目背景或长期决策时，应生成完整的 `CONTEXT_PACKAGE.md`。

---

# 3. 使用方式

当用户提出一个明确任务时，Agent 可以使用本模板生成：

```text
task_context/TASK_CONTEXT.md
```

生成前，Agent 应尽量参考：

```text
1. 用户当前任务说明
2. context/PROJECT_CONTEXT.md
3. context/USER_PREFERENCES.md
4. context/DECISION_LOG.md
5. context/TODO.md
6. context/TEST_COMMANDS.md
7. 当前任务相关文件
8. 已有 CONTEXT_PACKAGE.md
```

如果任务信息不足，Agent 不应编造，应写：

```text
缺失信息：
临时假设：
需要用户补充：
```

---

# 4. 什么内容应该写入 TASK_CONTEXT.md

应该写入：

```text
1. 当前任务原始需求
2. 任务目标
3. 任务范围
4. 输入材料
5. 预期输出
6. 相关文件
7. 关键约束
8. 执行步骤
9. 验证方式
10. 完成标准
11. 风险和不确定点
```

不应该写入：

```text
1. 完整项目长期背景
2. 用户所有长期偏好
3. 大量无关历史决策
4. 与本任务无关的完整文档
5. 详细变更日志
6. 完整实验数据库
7. 与任务无关的长聊天记录
```

这些内容应分别放入：

```text
context/PROJECT_CONTEXT.md
context/USER_PREFERENCES.md
context/DECISION_LOG.md
context/CHANGELOG.md
context/EXPERIMENT_LOG.md
task_context/CONTEXT_PACKAGE.md
```

## 5. 输入材料

本任务可用输入包括：


# 6. 任务状态定义

建议使用以下状态：

```text
Draft：任务信息不完整，仍在整理
Ready：任务信息完整，可以执行
Doing：正在执行
Blocked：被阻塞，暂时无法继续
Review：等待检查或用户确认
Done：已完成
Dropped：已放弃或不再需要
```

# 7. Agent 使用本模板的规则

Agent 生成 `TASK_CONTEXT.md` 时必须遵守：

```text
1. 保留用户原始需求。
2. 明确任务目标。
3. 明确本次做什么和不做什么。
4. 明确输入材料。
5. 明确预期输出。
6. 明确相关文件。
7. 明确关键约束。
8. 明确执行计划。
9. 明确验证方式。
10. 明确完成标准。
11. 标记风险和不确定点。
12. 不要编造不存在的文件、命令或输入。
```

---

# 8. 何时生成 TASK_CONTEXT.md

以下情况建议生成：

```text
1. 用户提出一个明确任务
2. 任务需要跨多步完成
3. 任务需要修改或生成文件
4. 任务需要验证
5. 任务边界容易混淆
6. 任务会进入 TODO.md
7. 任务需要后续追踪
```

以下情况通常不需要生成：

```text
1. 普通概念解释
2. 简单问答
3. 不需要追踪的临时聊天
4. 没有后续影响的小问题
```

# 9. Agent 生成 TASK_CONTEXT.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否保留用户原始需求？
2. 是否明确任务目标？
3. 是否明确任务范围？
4. 是否明确输入材料？
5. 是否明确预期输出？
6. 是否明确相关文件？
7. 是否明确关键约束？
8. 是否明确执行计划？
9. 是否明确验证方式？
10. 是否明确完成标准？
11. 是否标记不确定点？
12. 是否没有写入具体项目内容到模板本身？
```

---

# 10. 最终原则

```text
TASK_CONTEXT.md 是单个任务说明文件，不是项目长期背景文件，也不是完整上下文包。
```

它应该帮助 Agent 回答：

```text
这个任务到底要做什么？
怎么做才算完成？
完成后怎么验证？
```

如果需要完整项目背景和历史上下文，应生成：

```text
task_context/CONTEXT_PACKAGE.md
```
