# TODO_TEMPLATE.md

## 1. 模板作用

本模板用于生成项目任务清单文件：

```text
context/TODO.md
```

该文件用于记录项目中的当前任务、下一步任务、待办任务和已完成任务，帮助 Agent 和用户明确项目推进状态。

它主要回答：

```text
现在正在做什么？
下一步应该做什么？
还有哪些任务待处理？
哪些任务已经完成？
任务优先级是什么？
任务之间是否有依赖？
```

注意：

```text
本文件是通用模板，不绑定任何具体项目。
使用时，Agent 应根据当前项目实际情况，把【占位内容】替换为真实任务。
不要在模板中写入具体项目名称、具体技术路线或具体领域内容。
```

---

# 2. 使用方式

当 Agent 初始化一个项目，或用户要求建立任务清单时，应读取本模板，并生成：

```text
context/TODO.md
```

生成前，Agent 应尽量参考：

```text
1. 用户当前任务说明
2. PROJECT_CONTEXT.md
3. DECISION_LOG.md
4. README.md
5. 当前项目目录结构
6. 已有任务列表
7. CHANGELOG.md
8. task_context/CONTEXT_PACKAGE.md
```

如果没有明确任务，不要编造，应写：

```text
当前暂无明确任务，等待用户补充。
```

---

# 3. 什么内容应该写入 TODO.md

应该写入：

```text
1. 当前正在执行的任务
2. 下一步准备执行的任务
3. 未来待办任务
4. 已完成任务
5. 任务优先级
6. 任务状态
7. 任务依赖关系
8. 任务完成标准
9. 任务负责人或执行主体，如用户 / Agent / 人工确认
```

不应该写入：

```text
1. 长期项目背景
2. 详细技术决策
3. 用户长期偏好
4. 详细代码变更记录
5. 实验完整数据
6. 大段文档内容
7. 单次聊天解释
8. 未确认且无依据的任务
```

这些内容应分别放入：

```text
PROJECT_CONTEXT.md
DECISION_LOG.md
USER_PREFERENCES.md
CHANGELOG.md
EXPERIMENT_LOG.md
task_context/CONTEXT_PACKAGE.md
```

---

# 4. 任务状态定义

建议使用以下任务状态：

```text
Backlog：未来可能做，但暂不排期
Next：下一步准备做
Doing：正在做
Blocked：被阻塞，暂时无法继续
Review：等待检查或确认
Done：已完成
Dropped：已放弃或不再需要
```

---

# 5. 任务优先级定义

建议使用以下优先级：

```text
P0：最高优先级，必须尽快处理
P1：高优先级，近期处理
P2：中优先级，正常排期
P3：低优先级，有空再做
```

如果项目不需要优先级，可省略。

# 6. TODO.md 标准模板

复制下面内容，并根据当前项目实际情况填写。

```markdown
# TODO

## 1. 文件作用

本文件用于记录项目当前任务状态。

Agent 在处理任务时，应读取本文件，用于理解：

```text
当前正在做什么？
下一步应该做什么？
哪些任务已经完成？
哪些任务被阻塞？
任务之间有什么依赖？
```

本文件不记录长期项目背景、详细技术决策或完整变更记录。

---

## 2. 当前任务总览

```text
当前阶段：
【填写当前阶段】

当前重点：
【填写当前重点】

当前最优先任务：
【填写当前最优先任务】

当前阻塞点：
【填写当前阻塞点，如无则写“暂无明确阻塞点”】
```

---

## 3. Doing：正在进行

| ID | 优先级 | 任务 | 目标 | 负责人 | 开始时间 | 完成标准 | 备注 |
|---|---|---|---|---|---|---|---|
| T-001 | 【P0/P1/P2/P3】 | 【任务名称】 | 【任务目标】 | 【用户/Agent/其他】 | 【YYYY-MM-DD】 | 【完成标准】 | 【备注】 |

```

## 5. Backlog：未来待办

```text
暂无阻塞任务。
```

|---|---|---|---|---|---|---|

```

## 8. Done：已完成

| ID | 完成时间 | 任务 | 完成内容 | 输出文件 / 结果 | 验证情况 | 备注 |

| T-006 | 【YYYY-MM-DD】 | 【任务名称】 | 【完成内容】 | 【输出文件或结果】 | 【已验证/未验证/不适用】 | 【备注】 |

如果没有已完成任务，写：

```text

```

## 9. Dropped：已放弃 / 不再需要

如果没有已放弃任务，写：

```text

```

## 10. 任务依赖关系

```text
【任务 A】依赖【任务 B】
【任务 C】必须在【任务 D】完成后执行
【任务 E】可以并行执行
```

如果暂无依赖关系，写：

```text
暂无明确任务依赖关系。
```

---

## 11. 任务命名规则

建议任务 ID 使用：

```text
T-001
T-002
T-003
```

也可以根据项目需要扩展为：

```text
CODE-001
DOC-001
EXP-001
FIX-001
REVIEW-001
```

如果项目没有特殊要求，使用默认 `T-编号`。

---

## 12. 何时更新本文件

以下情况发生时，应更新本文件：

```text
1. 新增任务
2. 完成任务
3. 任务进入 Doing
4. 任务进入 Review
5. 任务被阻塞
6. 任务被放弃
7. 任务优先级变化
8. 任务依赖关系变化
9. 任务完成标准变化
10. 任务输出文件或验证状态变化
```

以下情况通常不更新本文件：

```text
1. 普通概念解释
2. 单次临时讨论
3. 长期项目目标变化
4. 用户长期偏好变化
5. 详细技术决策变化
6. 详细文件变更记录
```

这些内容应更新对应文件：

```text
PROJECT_CONTEXT.md
USER_PREFERENCES.md
DECISION_LOG.md
CHANGELOG.md
```

# 7. Agent 更新 TODO.md 的规则

Agent 在任务结束后，应根据 `TASK_CLOSING_CHECKLIST.md` 判断是否更新 TODO。

更新方式：

```text
1. 如果任务开始执行：
   从 Next / Backlog 移动到 Doing。

2. 如果任务完成：
   从 Doing / Review 移动到 Done。

3. 如果任务需要用户确认：
   移动到 Review。

4. 如果任务被阻塞：
   移动到 Blocked，并说明阻塞原因。

5. 如果任务不再需要：
   移动到 Dropped，并说明原因。

6. 如果产生新任务：
   添加到 Next 或 Backlog。
```

---

# 8. Agent 生成 TODO.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否区分 Doing / Next / Backlog / Blocked / Review / Done / Dropped？
2. 是否说明当前阶段和当前重点？
3. 是否有任务 ID？
4. 是否有任务优先级？
5. 是否有完成标准？
6. 是否有任务依赖？
7. 是否没有写入长期背景？
8. 是否没有写入详细决策？
9. 是否没有写入详细变更记录？
10. 是否说明何时更新本文件？
11. 是否没有写入具体项目内容到模板本身？
```

---

# 9. 最终原则

```text
TODO.md 是任务状态文件，不是项目背景文件，也不是决策记录文件。
```

它应该帮助 Agent 回答：

```text
现在做什么？
下一步做什么？
哪些已经完成？
哪些被阻塞？
```

如果是长期背景，应写入：

```text
context/PROJECT_CONTEXT.md
```

如果是长期决策，应写入：

```text
context/DECISION_LOG.md
```

如果是文件变更，应写入：

```text
context/CHANGELOG.md
```
