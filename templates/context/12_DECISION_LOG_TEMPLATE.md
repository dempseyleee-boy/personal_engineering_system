# DECISION_LOG_TEMPLATE.md

## 1. 模板作用

本模板用于生成项目长期决策记录文件：

```text
context/DECISION_LOG.md
```

该文件用于记录项目推进过程中已经确定的重要决策，帮助 Agent 和用户避免反复推翻已确认的方向。

它主要回答：

```text
之前已经决定了什么？
为什么这样决定？
这个决策影响哪些范围？
以后是否可以修改？
如果出现冲突，应该以哪个决策为准？
```

注意：

```text
本文件是通用模板，不绑定任何具体项目。
使用时，Agent 应根据当前项目实际情况，把【占位内容】替换为真实决策。
不要在模板中写入具体项目名称、具体技术路线或具体领域内容。
```

---

# 2. 使用方式

当 Agent 初始化一个项目，或用户要求建立长期决策记录时，应读取本模板，并生成：

```text
context/DECISION_LOG.md
```

生成前，Agent 应尽量参考：

```text
1. 用户当前明确说明
2. 项目已有 README / 文档 / 规则文件
3. 已有 PROJECT_CONTEXT.md
4. 已有 USER_PREFERENCES.md
5. 历史任务中已经确认的方案
6. 已有技术路线、目录结构、执行流程或约束
```

如果没有明确决策，不要编造，应写：

```text
当前暂无长期决策记录，后续在项目推进过程中补充。
```

---

# 3. 什么内容应该写入 DECISION_LOG.md

应该写入：

```text
1. 项目技术路线决策
2. 文件组织方式决策
3. 工具链选择决策
4. 工作流决策
5. 测试 / 验证方式决策
6. 模板和 Skill 使用方式决策
7. 长期约束决策
8. 重要取舍决策
9. 会影响后续多个任务的规则
```

不应该写入：

```text
1. 单次临时想法
2. 普通 TODO
3. 已经废弃且无参考价值的讨论
4. 未经用户确认的猜测
5. 单次报错信息
6. 单次实验结果
7. 详细变更记录
8. 具体代码 diff
```

这些内容应分别放入：

```text
context/TODO.md
context/CHANGELOG.md
context/EXPERIMENT_LOG.md
task_context/CONTEXT_PACKAGE.md
```

# 4. DECISION_LOG.md 标准模板

复制下面内容，并根据当前项目实际情况填写。

```markdown
# Decision Log

## 1. 文件作用

本文件用于记录项目中的长期重要决策。

Agent 在处理任务时，应读取本文件，用于理解：

```text
哪些方案已经确定？
哪些方向不能随意推翻？
哪些历史选择会影响当前任务？
如果上下文冲突，哪些决策更可信？
```

本文件不记录普通 TODO、临时讨论或单次任务过程。

---

## 6. 决策冲突处理规则

当不同文件或历史记录出现冲突时，按以下原则处理：

```text
1. 当前用户明确指令优先。
2. 项目根目录规则文件优先于普通文档。
3. 最新生效决策优先于旧决策。
4. 生效中的决策优先于待确认决策。
5. 已废弃决策不得作为当前执行依据，只能作为历史参考。
6. 如果冲突无法判断，Agent 必须说明冲突点，并请求用户确认。
```

## 7. 何时更新本文件

只有以下情况发生时，才更新本文件：

```text
1. 用户明确确认一个长期方案
2. 项目确定一个长期技术路线
3. 项目确定一个长期工作流
4. 项目确定一个文件组织方式
5. 项目确定一个工具链或验证方式
6. 旧决策被废弃或替代
7. 历史决策出现冲突，需要澄清
8. Agent 在任务结束后判断本次任务产生了长期决策
```

以下情况通常不更新本文件：

```text
1. 单次任务要求
2. 临时想法
3. 普通 TODO
4. 小范围代码修改
5. 单次实验结果
6. 未经用户确认的推测
```

# 5. Agent 生成 DECISION_LOG.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否只记录长期重要决策？
2. 是否避免写入普通 TODO？
3. 是否避免写入单次任务细节？
4. 是否为每条决策写明原因？
5. 是否写明影响范围？
6. 是否写明当前状态？
7. 是否写明是否可变更？
8. 是否记录相关文件？
9. 是否区分生效决策、废弃决策和待确认决策？
10. 是否说明何时更新本文件？
11. 是否没有写入具体项目内容到模板本身？
```

---

# 6. 最终原则

```text
DECISION_LOG.md 是长期决策记录文件，不是任务日志文件。
```

它应该帮助 Agent 回答：

```text
这个项目之前已经决定过什么？
当前任务不能违背哪些长期决策？
如果新旧信息冲突，应该怎么判断？
```

如果只是当前任务的一次性要求，应写入：

```text
task_context/CONTEXT_PACKAGE.md
```

如果只是任务清单，应写入：

```text
context/TODO.md
```

如果只是文件变更，应写入：

```text
context/CHANGELOG.md
```
