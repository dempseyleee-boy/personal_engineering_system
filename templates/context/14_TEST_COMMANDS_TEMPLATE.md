# TEST_COMMANDS_TEMPLATE.md

## 1. 模板作用

本模板用于生成项目验证命令文件：

```text
context/TEST_COMMANDS.md
```

该文件用于记录项目中可复用的运行命令、测试命令、构建命令、格式检查命令、验证命令和复现命令。

它主要回答：

```text
这个项目怎么运行？
怎么测试？
怎么构建？
怎么检查格式？
怎么验证修改是否正确？
怎么复现实验或结果？
Agent 修改项目后应该运行哪些命令？
```

注意：

```text
本文件是通用模板，不绑定任何具体项目。
使用时，Agent 应根据当前项目实际情况，把【占位内容】替换为真实命令。
不要在模板中写入具体项目名称、具体技术路线或具体领域内容。
```

---

# 2. 使用方式

当 Agent 初始化一个项目，或用户要求建立验证命令文件时，应读取本模板，并生成：

```text
context/TEST_COMMANDS.md
```

生成前，Agent 应尽量参考：

```text
1. README.md
2. package.json / pyproject.toml / requirements.txt / Makefile / CMakeLists.txt / build.gradle 等配置文件
3. scripts/ 目录
4. tests/ 目录
5. docs/ 目录
6. CI 配置文件
7. PROJECT_CONTEXT.md
8. TODO.md
9. 用户当前说明
```

如果没有找到明确命令，不要编造，应写：

```text
当前暂无明确命令，需要用户补充或后续根据项目结构推导。
```

# 3. 什么内容应该写入 TEST_COMMANDS.md

应该写入：

```text
1. 环境准备命令
2. 依赖安装命令
3. 项目运行命令
4. 单元测试命令
5. 集成测试命令
6. 构建命令
7. 格式化命令
8. 静态检查命令
9. 类型检查命令
10. 文档生成命令
11. 实验复现命令
12. 部署前验证命令
13. 手动验证步骤
```

不应该写入：

```text
1. 项目长期背景
2. 用户长期偏好
3. 技术决策解释
4. 详细 TODO
5. 详细变更记录
6. 与验证无关的长篇说明
7. 未经确认的危险命令
8. 会删除或覆盖重要数据的命令，除非明确标注风险
```

这些内容应分别放入：

```text
PROJECT_CONTEXT.md
USER_PREFERENCES.md
DECISION_LOG.md
TODO.md
CHANGELOG.md
```

# 4. 命令记录规范

每条命令建议包含：

```text
命令名称：
用途：
运行目录：
命令：
适用场景：
前置条件：
预期结果：
失败排查：
风险等级：
是否可由 Agent 自动执行：
```

风险等级建议使用：

```text
Low：只读、查看、普通测试、普通构建
Medium：会生成文件、修改缓存、安装依赖
High：会删除文件、覆盖数据、修改系统配置、访问外部服务
```

Agent 自动执行建议：

```text
Yes：可自动执行
Ask：执行前需要用户确认
No：禁止 Agent 自动执行，只能由用户手动执行
```

# 5. TEST_COMMANDS.md 标准模板

复制下面内容，并根据当前项目实际情况填写。

```markdown
# Test Commands

## 1. 文件作用

本文件用于记录项目可复用的运行、测试、构建和验证命令。

Agent 在处理项目任务时，应读取本文件，用于判断：

```text
修改后应该如何验证？
哪些命令可以自动执行？
哪些命令需要用户确认？
哪些命令有风险？
```

本文件不记录项目背景、长期决策或任务清单。

## 2. 命令使用总原则

```text
1. Agent 修改代码、文档、配置后，应优先查看本文件寻找验证命令。
2. Agent 不应编造不存在的命令。
3. 如果命令缺失，Agent 应说明缺失，并建议补充。
4. 高风险命令执行前必须询问用户。
5. 命令执行失败时，应记录失败原因和排查建议。
```

## 18. 何时更新本文件

以下情况发生时，应更新本文件：

```text
1. 新增运行命令
2. 新增测试命令
3. 新增构建命令
4. 新增格式化 / Lint / 类型检查命令
5. 新增实验复现命令
6. 新增手动验证步骤
7. 命令发生变化
8. 命令风险等级变化
9. 命令失败原因被确认
10. Agent 发现缺少验证方式
```

以下情况通常不更新本文件：

```text
1. 普通概念解释
2. 项目长期目标变化
3. 用户长期偏好变化
4. 普通 TODO 变化
5. 详细代码变更记录
6. 单次临时命令且不会复用
```

# 6. Agent 更新 TEST_COMMANDS.md 的规则

Agent 在任务结束后，应根据 `TASK_CLOSING_CHECKLIST.md` 判断是否更新本文件。

更新条件：

```text
1. 本次任务新增了可复用命令
2. 本次任务确认了已有命令的正确性
3. 本次任务发现已有命令失效
4. 本次任务需要补充验证方式
5. 本次任务发现某个命令有风险
6. 本次任务产生了新的手动验证步骤
```

不要因为只是读取了本文件就更新它。

---

# 7. Agent 生成 TEST_COMMANDS.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否区分运行、测试、构建、格式化、检查、验证命令？
2. 是否为每条命令注明运行目录？
3. 是否为每条命令注明用途？
4. 是否为每条命令注明预期结果？
5. 是否为每条命令注明风险等级？
6. 是否注明 Agent 是否可以自动执行？
7. 是否避免编造不存在的命令？
8. 是否记录缺失命令？
9. 是否说明何时更新本文件？
10. 是否没有写入具体项目内容到模板本身？
```

# 8. 最终原则

```text
TEST_COMMANDS.md 是验证命令文件，不是项目背景文件，也不是任务清单文件。
```

它应该帮助 Agent 回答：

```text
我改完以后该怎么验证？
哪些命令能自动跑？
哪些命令需要用户确认？
如果没有命令，我应该怎么说明？
```

如果是长期背景，应写入：

```text
context/PROJECT_CONTEXT.md
```

如果是任务清单，应写入：

```text
context/TODO.md
```

如果是文件变更，应写入：

```text
context/CHANGELOG.md
```
