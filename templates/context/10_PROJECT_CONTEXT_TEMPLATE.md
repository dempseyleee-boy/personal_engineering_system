# PROJECT_CONTEXT_TEMPLATE.md

## 1. 模板作用

本模板用于生成项目级长期上下文文件：

```text
context/PROJECT_CONTEXT.md
```

该文件用于让 Agent 快速理解一个项目的长期背景、目标、技术路线、当前阶段和固定约束。

注意：

```text
本文件是模板，不是具体项目内容。
使用时，Agent 应根据当前项目实际情况，把【占位内容】替换为项目真实信息。
```

---

# 2. 使用方式

当 Agent 进入一个新项目时，应先读取本模板，并基于项目实际情况生成：

```text
context/PROJECT_CONTEXT.md
```

生成前，Agent 应尽量读取：

```text
1. README.md
2. AGENTS.md / CLAUDE.md / Cursor Rules
3. 项目目录结构
4. package.json / pyproject.toml / requirements.txt / CMakeLists.txt 等配置文件
5. docs/ 目录
6. 用户当前说明
7. 已有 TODO / CHANGELOG / DECISION_LOG
```

如果信息不足，Agent 应明确写出：

```text
缺失信息：
临时假设：
需要用户补充：
```

---

# 3. 生成原则

`PROJECT_CONTEXT.md` 只记录长期稳定信息。

应该写入：

```text
1. 项目是什么
2. 为什么做
3. 长期目标是什么
4. 当前阶段是什么
5. 技术路线是什么
6. 关键环境是什么
7. 长期约束是什么
8. 何时需要更新本文件
```

不应该写入：

```text
1. 单次任务过程
2. 临时聊天记录
3. 详细 TODO 清单
4. 每次修改记录
5. 具体实验结果
6. 详细 Agent 执行步骤
7. 过长的未来规划
```

这些内容应分别放到：

```text
TODO.md
CHANGELOG.md
EXPERIMENT_LOG.md
DECISION_LOG.md
CONTEXT_PACKAGE.md
```

## 15. 适用 Agent 行为要求

Agent 在处理本项目任务时，应遵守：

```text
1. 先读取本文件理解项目背景。
2. 再读取 USER_PREFERENCES.md、DECISION_LOG.md、TODO.md、TEST_COMMANDS.md。
3. 对复杂任务先生成 task_context/CONTEXT_PACKAGE.md。
4. 不要在没有上下文的情况下直接执行复杂任务。
5. 修改项目后必须说明验证方式。
6. 任务结束后根据 TASK_CLOSING_CHECKLIST.md 判断是否更新长期文件。
```

---

## 16. 何时更新本文件

只有以下情况发生时，才更新本文件：

```text
1. 项目长期目标变化
2. 当前优先方向变化
3. 当前阶段变化
4. 技术路线变化
5. 软硬件环境变化
6. 长期约束变化
7. 项目整体结构发生重大变化
```

以下情况通常不更新本文件：

```text
1. 普通问答
2. 单次临时任务
3. 小范围代码修改
4. 单次 TODO 变更
5. 单次实验结果
6. 单次文档修改
```

# 5. Agent 生成 PROJECT_CONTEXT.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否说明项目名称？
2. 是否说明项目定位？
3. 是否说明长期目标？
4. 是否说明当前优先方向？
5. 是否说明当前阶段？
6. 是否说明技术路线？
7. 是否说明软硬件环境？
8. 是否说明长期约束？
9. 是否避免写入过多临时任务？
10. 是否说明何时更新本文件？
```

---

# 6. 最终原则

```text
PROJECT_CONTEXT.md 是长期背景文件，不是任务记录文件。
```

它应该帮助 Agent 回答：

```text
这个项目是什么？
当前长期方向是什么？
做任务时不能违背哪些长期约束？
```

而不是记录每一次具体对话。
