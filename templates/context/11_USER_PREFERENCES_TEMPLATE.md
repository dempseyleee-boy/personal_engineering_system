# USER_PREFERENCES_TEMPLATE.md

## 1. 模板作用

本模板用于生成用户长期偏好文件：

```text
context/USER_PREFERENCES.md
```

该文件用于让 Agent 理解用户在长期使用过程中的稳定偏好，包括：

```text
1. 回答风格偏好
2. 输出格式偏好
3. 技术路线偏好
4. Agent 行为偏好
5. 禁止默认项
6. 验证和交付偏好
7. 文档沉淀偏好
```

注意：

```text
本文件是通用模板，不绑定任何具体项目。
使用时，Agent 应根据当前用户和当前项目实际情况，把【占位内容】替换为真实信息。
不要在模板中写入具体项目名称、具体技术路线或具体领域内容。
```

---

# 2. 使用方式

当 Agent 初始化一个新项目，或用户要求建立长期偏好文件时，应读取本模板，并生成：

```text
context/USER_PREFERENCES.md
```

生成前，Agent 应尽量参考：

```text
1. 用户当前明确说明
2. 用户历史中反复表达的长期偏好
3. 当前项目已有规则文件
4. 当前项目已有 README 或说明文档
5. 当前项目已有 Prompt / Skill / Workflow 文件
```

如果某些偏好没有明确依据，Agent 不应编造，应写：

```text
暂无明确偏好，后续根据用户反馈补充。
```

---

# 3. 生成原则

`USER_PREFERENCES.md` 只记录长期稳定偏好。

应该写入：

```text
1. 用户长期喜欢的回答方式
2. 用户长期要求的输出格式
3. 用户长期技术偏好
4. 用户明确禁止的默认方案
5. 用户希望 Agent 遵守的工作方式
6. 用户对验证、文档、代码、实验或交付的长期要求
```

不应该写入：

```text
1. 单次任务的临时要求
2. 一次性聊天内容
3. 未经确认的猜测
4. 与用户长期工作无关的偏好
5. 过度私人化的信息
6. 项目具体 TODO
7. 单次实验结果
8. 详细变更记录
9. 具体项目名称或具体项目细节
```

这些内容应分别放入：

```text
task_context/CONTEXT_PACKAGE.md
context/TODO.md
context/EXPERIMENT_LOG.md
context/CHANGELOG.md
context/DECISION_LOG.md
```

---

# 4. USER_PREFERENCES.md 标准模板

复制下面内容，并根据用户真实偏好填写。

```markdown
# User Preferences

## 1. 文件作用

本文件用于记录用户长期稳定偏好。

Agent 在处理任务时，应读取本文件，用于理解：

```text
用户喜欢什么回答风格？
用户喜欢什么输出格式？
用户有哪些长期技术偏好？
用户明确不希望默认采用哪些方案？
Agent 执行任务时应该遵守哪些习惯？
```

本文件不记录单次任务的临时要求。单次任务要求应写入：

```text
task_context/CONTEXT_PACKAGE.md
```

---

## 2. 回答风格偏好

用户偏好的回答风格：

```text
1. 【偏好 1】
2. 【偏好 2】
3. 【偏好 3】
```

用户不喜欢的回答方式：

```text
1. 【不喜欢 1】
2. 【不喜欢 2】
3. 【不喜欢 3】
```

如果暂无明确偏好，写：

```text
暂无明确回答风格偏好，后续根据用户反馈补充。
```

---

## 3. 输出格式偏好

用户偏好的输出格式：

```text
1. 【输出格式偏好 1】
2. 【输出格式偏好 2】
3. 【输出格式偏好 3】
```

常用输出结构：

```text
1. 【结构 1】
2. 【结构 2】
3. 【结构 3】
```

如果用户在当前任务中指定特定格式，必须优先遵守用户当前指令。

---

## 4. 技术路线偏好

用户长期技术偏好：

```text
1. 【技术偏好 1】
2. 【技术偏好 2】
3. 【技术偏好 3】
```

如果暂无明确技术偏好，写：

```text
暂无明确技术路线偏好，后续根据项目推进补充。
```

注意：

```text
这里只记录长期技术偏好。
当前任务的临时技术限制应写入 task_context/CONTEXT_PACKAGE.md。
```

---

## 5. 禁止默认项

Agent 不应默认采用以下方案，除非用户明确要求：

```text
1. 【禁止默认项 1】
2. 【禁止默认项 2】
3. 【禁止默认项 3】
```

如果某项只是当前任务限制，不是长期限制，不应写入本文件，应写入：

```text
task_context/CONTEXT_PACKAGE.md
```

---

## 6. Agent 行为偏好

用户希望 Agent 在复杂任务中遵守：

```text
1. 【行为偏好 1】
2. 【行为偏好 2】
3. 【行为偏好 3】
4. 【行为偏好 4】
5. 【行为偏好 5】
```

可选方向：

```text
- 是否先读取项目结构
- 是否先制定计划
- 是否先说明假设
- 是否需要最小改动
- 是否需要验证结果
- 是否需要任务结束总结
- 是否需要建议更新长期文件
```

---

## 7. 文档与文件偏好

用户对文档和文件的长期偏好：

```text
1. 【文档偏好 1】
2. 【文档偏好 2】
3. 【文档偏好 3】
```

可选方向：

```text
- 是否优先使用 Markdown
- 是否需要可复用模板
- 是否需要 Agent 可读取规则文件
- 是否需要清晰目录结构
- 是否避免把多个主题混在一个文件
```

---

## 8. 代码任务偏好

用户对代码任务的长期偏好：

```text
1. 【代码偏好 1】
2. 【代码偏好 2】
3. 【代码偏好 3】
```

可选方向：

```text
- 是否先分析问题再写代码
- 是否要求完整可运行代码
- 是否要求最小改动
- 是否避免引入新依赖
- 是否要求测试命令
- 是否要求说明运行目录
- 是否要求无法验证时说明原因
```

如果当前用户不涉及代码任务，写：

```text
暂无明确代码任务偏好，后续根据项目需要补充。
```

---

## 9. 实验 / 研究 / 分析任务偏好

用户对实验、研究或分析类任务的长期偏好：

```text
1. 【偏好 1】
2. 【偏好 2】
3. 【偏好 3】
```

可选方向：

```text
- 是否要求实验目的
- 是否要求变量和对照组
- 是否要求评价指标
- 是否要求表格设计
- 是否要求结论写法
- 是否要求风险分析
```

如果当前用户不涉及实验或研究任务，写：

```text
暂无明确实验 / 研究 / 分析任务偏好，后续根据项目需要补充。
```

---

## 10. 验证偏好

用户希望 Agent 输出结果时尽量包含：

```text
1. 【验证偏好 1】
2. 【验证偏好 2】
3. 【验证偏好 3】
```

可选方向：

```text
- 如何验证结果正确
- 可以运行的测试命令
- 手动检查方法
- 风险点
- 未验证原因说明
```

长期原则：

```text
【填写用户对“完成”和“验证”的长期要求】
```

如果暂无明确验证偏好，写：

```text
暂无明确验证偏好，后续根据项目推进补充。
```

---

## 11. 任务结束偏好

任务结束时，用户希望 Agent 输出：

```text
1. 【收尾偏好 1】
2. 【收尾偏好 2】
3. 【收尾偏好 3】
```

可选方向：

```text
- 本次完成了什么
- 哪些内容未完成
- 有哪些风险
- 建议更新哪些长期文件
- 哪些文件不需要更新
- 下一步建议
```

如果任务产生长期价值，Agent 应建议更新对应长期文件，例如：

```text
context/PROJECT_CONTEXT.md
context/USER_PREFERENCES.md
context/DECISION_LOG.md
context/TODO.md
context/TEST_COMMANDS.md
context/CHANGELOG.md
context/EXPERIMENT_LOG.md
对应 Skill 文件
```

---

## 12. 何时更新本文件

只有以下情况发生时，才更新本文件：

```text
1. 用户明确表达新的长期偏好
2. 用户纠正 Agent 的回答风格
3. 用户明确说“以后都这样”
4. 用户明确禁止某种默认方案
5. 用户确定某种长期技术路线偏好
6. 用户对输出格式提出长期要求
7. 用户对 Agent 工作方式提出长期规则
```

以下情况通常不更新本文件：

```text
1. 单次任务要求
2. 临时格式要求
3. 一次性对话偏好
4. 当前任务的局部约束
5. 未经用户确认的推测
```

---

## 13. 当前不确定偏好

```text
1. 【不确定偏好 1】
2. 【不确定偏好 2】
3. 【需要用户确认的偏好】
```

如果没有，写：

```text
暂无明显不确定偏好。
```
```

---

# 5. Agent 生成 USER_PREFERENCES.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否只记录长期偏好？
2. 是否避免记录单次任务要求？
3. 是否有明确依据？
4. 是否没有编造用户偏好？
5. 是否包含回答风格偏好？
6. 是否包含输出格式偏好？
7. 是否包含技术路线偏好？
8. 是否包含禁止默认项？
9. 是否包含 Agent 行为偏好？
10. 是否说明何时更新本文件？
11. 是否没有写入具体项目内容？
```

---

# 6. 最终原则

```text
USER_PREFERENCES.md 是长期偏好文件，不是任务要求文件。
```

它应该帮助 Agent 回答：

```text
用户长期喜欢我怎么回答？
用户长期不希望我默认做什么？
用户长期希望任务怎么推进？
```

如果只是当前任务的一次性要求，应写入：

```text
task_context/CONTEXT_PACKAGE.md
```

而不是写入本文件。
