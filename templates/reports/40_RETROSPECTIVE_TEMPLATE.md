# RETROSPECTIVE_TEMPLATE.md

## 1. 模板作用

本模板用于生成阶段复盘文件：

```text
reports/RETROSPECTIVE.md
```

或按阶段生成：

```text
reports/retrospectives/RETROSPECTIVE_YYYY_MM_DD.md
```

该文件用于在一个任务、一个阶段、一次迭代或一个小项目完成后，系统性复盘：

```text
做了什么？
结果如何？
哪里做得好？
哪里出了问题？
哪些规则需要更新？
哪些模板需要优化？
哪些任务需要继续推进？
```

注意：

```text
本文件是通用模板，不绑定任何具体项目。
使用时，Agent 应根据当前项目或当前阶段实际情况，把【占位内容】替换为真实复盘内容。
不要在模板中写入具体项目名称、具体技术路线或具体领域内容。
```

---

# 2. 使用方式

当完成以下任一情况时，可以使用本模板生成复盘文件：

```text
1. 完成一个阶段性任务
2. 完成一批模板或规则文件
3. 完成一次代码重构
4. 完成一次实验设计或实验执行
5. 完成一次文档整理
6. 完成一次 Agent 工作流改进
7. 完成一个小版本迭代
8. 用户明确要求“复盘一下”
```

复盘文件通常不需要每次小问答都生成。

---

# 3. RETROSPECTIVE 与其他文件的区别

```text
TODO.md：
记录任务状态。

CHANGELOG.md：
记录实际文件变更。

DECISION_LOG.md：
记录长期重要决策。

AGENT_LESSONS.md：
记录 Agent 犯错和规则改进。

RETROSPECTIVE.md：
对一个阶段进行总结、反思和下一步规划。
```

# 5. Agent 使用本模板的规则

Agent 生成复盘文件时必须遵守：

```text
1. 只基于真实发生的任务和输出进行复盘。
2. 不要编造不存在的成果。
3. 不要把复盘文件当作变更日志。
4. 不要把复盘文件当作 TODO 清单。
5. 复盘中发现的任务，应建议写入 TODO.md。
6. 复盘中发现的决策，应建议写入 DECISION_LOG.md。
7. 复盘中发现的 Agent 错误，应建议写入 AGENT_LESSONS.md。
8. 复盘中发现的文件变更，应建议写入 CHANGELOG.md。
9. 复盘中发现的验证命令，应建议写入 TEST_COMMANDS.md。
```

# 6. 何时更新复盘文件

复盘文件通常是按阶段生成新文件，而不是频繁覆盖同一个文件。

推荐命名：

```text
reports/retrospectives/RETROSPECTIVE_YYYY_MM_DD.md
reports/retrospectives/RETROSPECTIVE_STAGE_NAME.md
```

如果项目较小，也可以维护一个：

```text
reports/RETROSPECTIVE.md
```

以下情况可以生成复盘：

```text
1. 完成一组模板
2. 完成一个 Skill
3. 完成一个阶段目标
4. 完成一次项目重构
5. 完成一次实验
6. Agent 出现多次类似问题
7. 用户要求总结当前阶段
```

---

# 7. Agent 生成 RETROSPECTIVE.md 后的检查清单

生成后，Agent 必须检查：

```text
1. 是否说明复盘范围？
2. 是否列出完成内容？
3. 是否列出未完成内容？
4. 是否分析做得好的地方？
5. 是否分析存在的问题？
6. 是否提出改进方向？
7. 是否说明是否需要更新长期文件？
8. 是否提出下一步任务？
9. 是否没有写入具体项目内容到模板本身？
10. 是否避免编造不存在的成果？
```

---

# 8. 最终原则

```text
RETROSPECTIVE.md 是阶段复盘文件，不是任务清单文件，也不是变更日志文件。
```

它应该帮助 Agent 和用户回答：

```text
这一阶段我们学到了什么？
下一阶段应该怎么做得更好？
哪些规则、模板或 Skill 应该更新？
```
