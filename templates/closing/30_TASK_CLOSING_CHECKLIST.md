# Task Closing Checklist

## 1. 文件作用

本文件用于任务结束后，由 Agent 检查本次任务是否产生了需要沉淀到长期上下文文件的信息。

它的目标是：

```text
任务完成后，不让经验、决策、命令、实验结果和规则改进散落在对话里。
```

Agent 不应该每次任务结束后盲目更新所有文件，而应该按本清单判断：

```text
哪些文件需要更新？
哪些文件不需要更新？
为什么？
下一步应该做什么？
```

---

# 2. 使用时机

Agent 在完成以下任务后，必须执行本检查清单：

```text
1. 生成或修改代码
2. 生成或修改文档
3. 新增 Skill / Prompt / 规则文件
4. 做出技术决策
5. 完成实验设计或实验记录
6. 修改项目结构
7. 新增测试命令
8. 发现 Agent 行为问题
9. 完成一个阶段性任务
```

对于简单问答，可以不更新长期文件，但仍可输出是否需要沉淀的判断。

---

# 3. 任务结束检查总流程

```text
任务完成
  ↓
总结本次完成内容
  ↓
检查是否影响长期上下文文件
  ↓
列出建议更新文件
  ↓
列出不需要更新文件
  ↓
如有必要，更新对应文件
  ↓
记录下一步建议
```

---

# 4. 标准检查清单

## 4.1 是否改变了项目长期目标？

检查问题：

```text
本次任务是否改变了项目目标、技术路线、当前阶段、硬件/软件环境或长期限制？
```

如果是，更新：

```text
context/PROJECT_CONTEXT.md
```

记录内容：

```text
1. 变化内容
2. 变化原因
3. 生效范围
4. 是否替代旧目标
```

如果否，写：

```text
PROJECT_CONTEXT.md 不需要更新，因为本次任务未改变项目长期背景或技术路线。
```

---

## 4.2 是否产生了新的用户长期偏好？

检查问题：

```text
用户是否表达了新的长期偏好、回答风格、技术偏好、输出格式偏好或禁止事项？
```

如果是，更新：

```text
context/USER_PREFERENCES.md
```

示例：

```text
用户偏好：
- 技术问题优先直接讲原理、流程、例子。
- FPGA 方案不要默认使用 HLS。
- 输出优先生成 Markdown 文件。
```

如果否，写：

```text
USER_PREFERENCES.md 不需要更新，因为本次任务未产生新的长期偏好。
```

---

## 4.3 是否产生了重要技术决策？

检查问题：

```text
本次任务是否确定了一个以后需要遵守的方案、路线、架构、文件组织方式或工作流？
```

如果是，更新：

```text
context/DECISION_LOG.md
```

记录格式：

```text
日期：
决策：
原因：
影响范围：
是否可变更：
相关文件：
```

示例：

```text
日期：2026-04-25
决策：采用“长期上下文文件 + 临时 Context Package”的上下文管理方式。
原因：便于长期沉淀，也便于每次任务压缩上下文。
影响范围：个人工程优化系统中的所有 Agent 任务。
是否可变更：可变更，但需要记录原因。
相关文件：CONTEXT_ENGINEERING_SKILL.md、CONTEXT_PACKAGE_TEMPLATE.md。
```

如果否，写：

```text
DECISION_LOG.md 不需要更新，因为本次任务没有产生新的长期决策。
```

---

## 4.4 是否新增、完成或调整了任务？

检查问题：

```text
本次任务是否产生了新的 TODO？
是否完成了已有 TODO？
是否改变了任务优先级？
```

如果是，更新：

```text
context/TODO.md
```

推荐结构：

```text
## Doing
- [ ] 当前正在做的任务

## Next
- [ ] 下一步任务

## Backlog
- [ ] 未来可做任务

## Done
- [x] 已完成任务
```

如果否，写：

```text
TODO.md 不需要更新，因为本次任务未改变任务清单。
```

---

## 4.5 是否新增或修改了验证命令？

检查问题：

```text
本次任务是否新增了运行、测试、构建、仿真、格式检查、实验复现命令？
```

如果是，更新：

```text
context/TEST_COMMANDS.md
```

记录格式：

```text
命令用途：
运行目录：
命令：
适用场景：
注意事项：
```

示例：

```bash
# 运行 Python 单元测试
pytest tests/

# Verilog lint 检查
verilator --lint-only rtl/top.v
```

如果否，写：

```text
TEST_COMMANDS.md 不需要更新，因为本次任务没有新增验证命令。
```

---

## 4.6 是否修改了代码、文档、配置或规则文件？

检查问题：

```text
本次任务是否创建、修改、删除了任何项目文件？
```

如果是，更新：

```text
context/CHANGELOG.md
```

记录格式：

```text
日期：
变更类型：
修改文件：
变更内容：
变更原因：
验证情况：
后续影响：
```

变更类型可选：

```text
代码
文档
配置
规则
实验
目录结构
Prompt
Skill
其他
```

如果否，写：

```text
CHANGELOG.md 不需要更新，因为本次任务未修改项目文件。
```

---

## 4.7 是否产生了实验设计或实验结果？

检查问题：

```text
本次任务是否设计了实验、完成了实验、产生了实验数据、表格、图表或结论？
```

如果是，更新：

```text
context/EXPERIMENT_LOG.md
```

记录格式：

```text
实验名称：
实验目的：
实验设置：
对照组：
评价指标：
实验结果：
结论：
问题：
下一步：
```

如果只是设计实验但还没跑实验，必须标记：

```text
状态：实验设计完成，尚未执行。
```

如果否，写：

```text
EXPERIMENT_LOG.md 不需要更新，因为本次任务没有产生实验设计或实验结果。
```

---

## 4.8 是否暴露了 Agent 规则问题？

检查问题：

```text
本次任务中 Agent 是否出现了以下问题？
1. 没读上下文就开始执行
2. 忽略用户偏好
3. 输出太泛
4. 忽略验证
5. 改了无关文件
6. 编造文件或命令
7. 没有处理上下文冲突
8. 没有生成 Context Package
```

如果是，更新对应文件：

```text
skills/PROMPT_ENGINEERING_SKILL.md
skills/CONTEXT_ENGINEERING_SKILL.md
skills/VERIFICATION_SKILL.md
templates/TASK_CLOSING_CHECKLIST.md
```

记录内容：

```text
问题：
触发场景：
修正规则：
以后如何避免：
```

如果否，写：

```text
Skill 文件不需要更新，因为本次任务没有暴露新的 Agent 规则问题。
```

---

## 4.9 是否值得沉淀为长期知识？

检查问题：

```text
本次任务是否产生了以后会反复使用的知识、模板、踩坑经验、实验方法或工程规范？
```

如果是，更新：

```text
knowledge_base/
```

推荐分类：

```text
knowledge_base/
├── PROMPT_ENGINEERING/
├── CONTEXT_ENGINEERING/
├── HARNESS_ENGINEERING/
├── FPGA/
├── YOLO/
├── PAPER_WRITING/
├── ERROR_FIXES/
├── EXPERIMENTS/
└── TEMPLATES/
```

如果否，写：

```text
knowledge_base/ 不需要更新，因为本次任务没有产生需要长期复用的知识。
```

# 6. 自动更新规则

如果 Agent 具备文件写入权限，可以在用户允许或任务规则允许的情况下自动更新长期文件。

但以下情况必须先询问用户或明确说明：

```text
1. 删除文件
2. 大规模重构目录
3. 覆盖已有长期决策
4. 修改核心项目目标
5. 修改安全相关规则
6. 修改多个 Skill 文件
7. 清空 TODO / CHANGELOG / DECISION_LOG
```

如果 Agent 没有文件写入权限，应输出：

```text
我建议更新以下文件：
1. 【文件路径】
2. 【文件路径】

下面是建议写入内容：
【给出可复制内容】
```

---

# 7. 不应更新的情况

以下情况通常不需要更新长期文件：

```text
1. 普通概念解释
2. 临时问答
3. 没有形成新决策
4. 没有改变项目状态
5. 没有新增任务
6. 没有产生实验结果
7. 没有新增验证命令
8. 没有暴露新的 Agent 规则问题
```

但如果用户明确要求“记下来”“写入文档”“保存为规则”，则应更新对应文件。

---

# 8. 最终原则

```text
任务开始靠 Context Package。
任务结束靠 Task Closing Checklist。
```

目标：

> 让每次任务都形成闭环：开始前看对上下文，结束后沉淀有价值的信息。
